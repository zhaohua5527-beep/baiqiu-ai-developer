# 重复“当前会话已有任务”提示

## 根因

主进程在 product:submit-task 入口会先检查 activeRuns。已有任务时返回 RUN_ALREADY_ACTIVE，因此后端没有启动第二个任务。

渲染端此前在调用该入口之前已经把新用户消息写入会话并显示出来。收到 busy 结果后，仍把结果当作普通助手答案渲染和持久化。用户再次点击就会重复这个过程，于是出现多组：

    用户问题
    当前会话已有任务正在执行……

这不是模型重复生成，也不是任务真的启动了多次；是“未启动请求”被错误当成普通对话结果显示。

## 修复

- 统一识别 status: busy 和 error: RUN_ALREADY_ACTIVE。
- 忙碌结果在进入普通答案渲染前处理，不生成助手消息，不写入失败答案。
- 删除这次未启动请求刚写入的临时用户消息；删除接口只接受 role: user，按精确消息 ID 操作。
- 将用户原输入、附件和引用恢复到输入框，用户可以等当前任务结束后重新发送或加入补充队列。
- 保留主进程已有的每会话任务锁和提交幂等逻辑。

现有截图中的重复记录不会被自动批量删除，避免误删用户真实问题；修复从下一次发生 busy 返回开始生效。

## 验证

request-lifecycle-regressions.test.js 的 busy 提交定向测试通过；input-scroll-performance.test.js 也通过，确认输入和历史滚动优化没有回归。主进程、preload 和渲染脚本语法检查通过。

当前运行窗口没有重启。要让这次主进程、preload 和渲染端改动生效，需要先处理现有任务，再完全退出并重新打开“白球AI-测试-11”。
