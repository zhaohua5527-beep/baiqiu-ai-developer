# 执行时显示当前操作（2026-09-17）

## 已定位的机制

`services/hms-progress.js` 原先将带有任何结果内容的 `tool_call_update` 判为完成，即使状态明确为 `running` 或 `in_progress`。因此工具的中间输出可能提前结束工具状态。

`renderer-v2/app.js` 原先在阶段回复结束后折叠所属执行过程，未检查其中是否仍有活跃工具。默认事件窗口只有 62px，并带渐隐遮罩，也会使具体命令难以阅读。

上述是代码与回归用例确认的问题；不能据此认定所有历史卡死均由这些问题造成。

## 改动

- 显式执行中状态优先于结果是否非空；无状态的旧式最终结果继续兼容。更新保留工具 ID、输入、输出与事件身份。
- 搜索摘要带实际目录和关键词，读取摘要带文件路径，终端摘要带已脱敏命令。原始公开输入和输出仍保留在执行详情中。
- 小剧场下方显示当前操作。按会话轮次和工具 ID 分别显示并行工具，以事件序号判断最新状态，晚到的旧事件不重新激活已结束工具。
- 等待文字仅表示“等待工具后续事件 / 等待黑球后续事件”和距最后事件的秒数，不表示远端一定仍在工作。复用原来的计时器，不每秒重新扫描历史。
- 阶段性回复不折叠仍有活跃工具的过程。活跃工具详情取消渐隐，超过 180px 可滚动查看。
- 完成或中断后停止当前操作提示，已收到的执行内容仍保存在原有历史中。
