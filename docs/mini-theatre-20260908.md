此文记录的是已被用户否定的图形角色版本，仅保留为历史记录。当前实现已改为文字动画与连续剧情，见 [文字小剧场重做](text-theatre-20260908.md)。

2026-09-08，版本 3.0.22。按用户最新直接执行授权，先审计再实施，仅改造前端本地小剧场。审计记录位于 `C:/Users/Lenovo/Desktop/白球AI-客户端/work/mini-theatre-20260908/审计与方案.md`。

## 新体验

剧场为消息滚动区之外的独立容器，固定在当前任务内容上方。每个任务只创建一次，镜头在同一个 SVG 内切换：看电脑、翻资料、敲键盘、用放大镜查看地图、搬文件到设备、看时钟等待。每个镜头约 4.4—5.4 秒，过渡约 300 毫秒；角色、手脚、眼睛、道具、数据光点和扫描线持续运动，不再只是文案轮换。

收到真实结束状态后，分别播放庆祝、异常停止、收工具动画，然后冻结。等待用户输入作为静止等待状态，不假定任务成功。显示从任务开始时间计算的真实经过秒数，结束后冻结。动画场景仅是本地陪伴画面，不声称对应实际工具调用。

## 修改文件

- `renderer-v2/mini-theatre.js`：独立的本地状态机、角色和道具 SVG 素材池、场景组合配置、生命周期与资源管理。
- `renderer-v2/mini-theatre.css`：角色动作、场景过渡、镜头轻微缩放、特效、三种收尾、冻结、深色模式及窄屏样式。沿用页面字体。
- `renderer-v2/index.html`：增加独立宿主，并加载新模块和样式；宿主在 conversationStage 外，不属于 messageList。
- `renderer-v2/app.js`：从任务开始、结果、失败、取消、会话选择、页面离开入口单向通知剧场。删除原文字轮换调度入口和消息内的小剧场容器。
- `test/mini-theatre.test.js`：组件唯一性、六镜头持续轮换、成功/失败/取消/等待终态、结束计时冻结、监听清理、后台暂停、会话切换、后台完成画面恢复、减少动态效果与展示边界。

旧文字素材与部分辅助函数仍作为未调用的旧代码保留，因为它们与执行过程 flow 的历史结构交织；旧剧场调度入口已经删除，不会并行播放或写入旧剧场 localStorage。没有为清理旧代码扩大到执行流程重构。

## 生命周期和边界

运行时状态为 RUNNING / SCENE_TRANSITION，终态为 ENDING_SUCCESS / ENDING_FAILURE / ENDING_CANCELLED，最后为 FROZEN。宿主为空时隐藏，等同于空闲。真实任务状态只作为输入，小剧场没有反向任务控制能力。

只有可见任务使用一个本地定时器。离开会话或页面隐藏时暂停；后台完成立即冻结。结束动画结束后停止计时、移除 visibilitychange 监听，不创建 Observer。页面离开销毁全部本地节点和资源。每个会话只保留最近一个任务画面；最多缓存 24 个后台冻结画面，避免跨会话长时间积累。

组件没有模型、IPC、网络、聊天存储和执行事件依赖，不消费模型 Token，不进入模型上下文，不产生业务事件。正文、交叉回复、执行流、阶段结果、后端和模型设置没有改动。

## 验证结果

本轮相关回归 **34/34 通过**：其中小剧场专项 10 项，其余为既有阶段显示和通道隔离回归。JavaScript 语法及 diff 检查通过。

Electron 独立视觉检查覆盖六个镜头，观察到打字手臂的变换随时间变化，确认不是图片轮播。检查了深色配色和 420px 窄窗口，没有横向溢出。独立预览中的多个容器是不同镜头的验收展示，不是业务页面的多任务布局。

真实桌面测试：

- 任务运行：首个观察样本约 13ms 已有本地剧场，全程最多一个容器；真实任务成功后进入 FROZEN，计时停止，滚动消息时位置不变，聊天历史没有剧场内容。
- 用户取消：向实际测试任务发送取消请求，页面收到“任务已终止”，剧场进入 cancelled → FROZEN，计时停止。
- 后台完成：任务开始后切到其他会话，任务真实返回 OK，再回到任务会话时保留 success / FROZEN 画面，计时停止。初测发现提前清理冻结画面，已修复并重测通过。
- 失败收尾由独立组件生命周期测试覆盖；本轮没有为视觉验收伪造后端失败事件。

首次成功测试的模型回答带有额外无关文字，剧场本身没有写入这些内容；这是模型回答行为，本轮不扩大到回答处理。该测试仅证明生命周期和剧场显示正常，不作为模型遵循“只回复 OK”的验收通过证据。后续后台任务实际只返回 OK。
