## 修改

- 公开阶段结果与 cross 使用 v2：第一行 JSON 元数据（schemaVersion、segmentId、类型、状态、证据 ID），换行后为原始 Markdown，结束标签独占一行。正文不再作为 JSON 字符串，避免普通引号破坏解析。原有格式继续兼容。
- JavaScript 流式解析、整段收尾清理、Python 阶段审查与协议恢复均支持同一格式。代码围栏中的示例标签不作为协议边界；非法嵌套、缺失身份、截断和混用 message 字段会拒绝，不能伪造成已完成结果。原始源文保留。
- 原生恢复器针对“闭合的旧进度格式异常、普通最终正文存在、finish_reason 为 stop、无未结束或状态不明工具”发送 warning，不额外调用模型。客户端对 warning 不清空流、不重置答案归属。截断、工具协议泄漏、缺失正文等仍走有界恢复或失败路径。
- 修复需要恢复的提示：明确仅补充缺失内容，不能重复已交付答案或已完成工具。
- 状态栏根据现有 transport_activity 显示接口仍有数据或距上次数据的秒数。工具等待计时保持独立，传输数据不充当公开任务进度、不重置正文超时预算。首次思考通道活动只映射为无内容的生成状态，不公开私有思考文本。
- 用户只纠正一个数据时，公开协议指引先回答变化，仅缺少必要证据时再查询。不更改用户推理等级，不另设执行路由。
- 既有按需上下文策略的默认值从 shadow 改为 on，仍受明确配置、供应商/端点/型号白名单、本地环境、可读工具与历史边界约束。加入本次实际 DeepSeek 官方模型标识。只转存较旧、成功且与当前关键词不匹配的长工具输出，原文经校验落在当前用户目录，失败时保留完整请求。
- 图片与历史推理字段没有删除；后者在部分供应商的工具循环中是必需协议字段。新增 imageCount/imageDataChars 诊断，避免把图片编码误称为正文长度，不记录图片或推理内容。
