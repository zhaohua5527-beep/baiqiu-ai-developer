# 模型配置保存与切换修复

## 范围

修改实际测试版源码 source-current（3.0.27）的模型配置保存、切换、启停、删除与推理等级入口。没有修改用户的真实 API Key、聊天数据库、快捷方式或版本号，没有重启当前窗口，也没有发布安装包。

## 已定位的机制

- API Key 输入框在提交时被旧配置重绘，只要旧 Key 存在就提前显示“已保存”；验证失败状态也可能被已配置条件清掉。
- 普通设置表单携带旧模型字段，能覆盖刚确认的模型配置；旧会话快照同样可能回退前端选中状态。
- 模型保存与目录刷新原来克隆整个数据库并走同步落盘路径，保存模型配置的开销被聊天历史放大。
- 应用运行配置会停止已有模型客户端，未等当前任务结束；后台预热也可能在新配置尚未持久化时应用旧快照。

## 修改后的行为

1. 输入草稿与已确认配置分离，提交只允许一个进行中的操作。界面显示真实的验证、等待当前任务、应用与落盘阶段；收到已提交版本回执后才显示成功。
2. 模型操作在主进程串行执行，校验旧配置版本；普通设置与旧会话快照不能覆盖已确认模型字段。失败保留草稿，并轻量读取后台实际配置。
3. 有任务运行时先等待；新任务等待模型切换，不互相形成死锁。等待超时明确报错，不杀掉旧任务。Agent 自己申请切换返回 pending，任务结束后再处理。
4. 运行配置应用和持久化之间设提交屏障。后台预热等待提交或回滚，并使用权威模型字段，不能把新配置恢复成旧快照。
5. 模型配置使用独立的小 JSON 记录异步原子替换，成功落盘才更新内存。普通设置保存仍沿用原数据库机制，但合并到最新数据库，保留期间新增的会话结果。
6. 连接测试只测试，不再整份保存设置或重新读取全部聊天记录；模型目录刷新只缓存匹配当前凭证的目录信息。

## 持久化与回退注意

- 新文件为用户数据目录中的 model-settings.json。没有该文件时继续读取原数据库配置，首次成功模型保存或目录缓存后建立记录。
- 字段范围：providers、defaultProvider、reasoning、modelRuntime、modelConfigRevision、modelConfigGeneration。
- 该文件含模型凭证，必须与用户数据一起备份，不能上传、提交源码或出现在诊断日志中。操作日志只记录请求 ID、结果和阶段耗时。
- 回退旧代码前，应核对旧版数据库中的模型字段是否已同步到最新；不能直接删除此记录，也不能假设旧版程序能读取它。回退必须保留当前用户数据和凭证。
- 改动前源码备份位于 work/model-settings-20260929-003321；存在其他既有未提交修改，禁止整仓 reset。

## 生效方式

主进程、preload 与渲染脚本都已修改，需要先处理当前任务与待发送补充队列，再完全退出并重新打开“白球AI-测试-11”。仅关闭窗口到托盘或刷新页面不能使全部改动生效。本次没有代用户重启或发布顾客版本。
