# 阅读位置与收尾布局修正

## 范围

- `renderer-v2/app.js` 和 `renderer-v2/styles.css`；未改模型、事件内容、用户数据、版本和发布包。
- 改动前源码及修改到的既有测试保存在 `work/viewport-stability-20260930-005929`。

## 修改

1. 已接收字节显示为紧凑的 `已接收1000KB`，移除数字的 7ch 最小宽度及内部空格。继续使用实际累计字节和同一数字节点，不制造进度。
2. 收到终止帧时不再提前收起执行区域；等永久答复绑定、已接收文字显示完毕后，由原有 finalize 流程统一收尾。
3. 收尾复用原头部、黑球和计数节点；重复收尾不强制关闭用户手动展开的历史。执行态与完成态使用相同头部最小高度和间距。
4. 执行事件更新、等待提示变化、过程收起与最终收尾通过现有视口事务保持阅读锚点。手动阅读时锚定可见正文块，而不只是整条长消息的顶部。
5. 会话切换先保存位置并取消旧会话的滚动任务；返回时同步恢复保存的消息锚点与偏移，已保存位置优先于旧指令锁定。缓存恢复与历史重建共用这一规则。
6. 保存时位于底部、离开后又增加内容的会话，恢复后不会因为旧的 atBottom 标志立即追到底部；首次打开仍保留现有默认行为。

## 验证状态

只做源码和差异审查，补充/调整了回归用例。按用户要求，未运行测试、语法检查、构建或模型请求，未重启客户端、打包或发布；不能据此声称真机抖动已经完全消失。

获得测试授权后核验：A→B→A 返回位置；快速连切；正在输出的会话；缓存淘汰后重建；离开期间新增消息；完成前后头部/黑球节点不替换；过程收起时可见正文不跳；重复完成事件后展开历史不被关闭；窄窗口、字体缩放及 KB 跨位数增长。
