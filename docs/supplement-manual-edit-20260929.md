## 草稿与发送

- 新建待补充默认 autoStart:false。打字、粘贴、编辑、失焦、保存草稿以及当前任务结束，不会授权发送。
- 任务执行中，在主输入框按 Enter 或 Alt+Enter 会保存到待补充；点击主发送按钮才立即提交。普通空闲聊天保留原来的 Enter 发送习惯。
- 待补充条目内的 Enter 用于换行；只有点击箭头才提交。发送时使用最新编辑内容。
- 已确认发送的条目可以在安全节点自动接续；未确认草稿不阻塞其他已确认条目。附带文件或引用仍沿用保留完整内容的下一轮发送路径。
- 收到未知回执时只核对原 ID，不重新创建同一任务。发送中的条目不能修改，以免改变已提交请求。

## 原位编辑

- 点击条目铅笔后，文字所在位置切换为输入框，不弹窗、不替换主输入框草稿。
- 勾选保存仅保存待补充；叉号或 Escape 撤销本次编辑；箭头保存最新内容并提交。
- 后台队列刷新复用正在编辑的 DOM 节点；附件、引用及上下文不丢弃，输入法组合期间不提交。

## 黑球当前任务语义

- 补充使用独立的 Active task supplement 标记，不再复用替换式 User request 标记。
- 请求边界保留本轮最初目标和未完成要求；只有用户明确取消或替换时才改变原目标，不自动恢复更早轮次的任务。
- 补充进入当前任务的判断、后续行动和阶段成果。有后续工作时由黑球生成真实的公开调整说明；没有额外工作时允许直接交付综合答案，不制造过程卡或公开私有推理。
- 回应补充与完成整任务分离。有补充的任务需在最终元数据声明 taskCompletion：status:completed、scope:active_task、当前 turnId、全部 supplementIds；阶段成果仍引用真实 deliveredSegmentIds。运行时及消费端校验范围与输出证据。
- 缺失整任务声明保留 incomplete，不以 addressed 自动认定原任务已完成。模型的完成声明仍须通过实际行为验收，不能当作理解正确的客观证明。

## 未执行的验收清单

1. 运行中用 Enter 留一条待补充；不点击箭头，等任务结束，确认未发出请求。
2. 在条目原地修改，触发后台刷新，确认光标、输入内容和主输入框草稿保持；保存或失焦不发送。
3. 点击箭头发送最新修改，快速重复点击，确认同一 ID 不重复执行；检查附件与引用保留。
4. 原指令“比较三个方案并给执行顺序”，运行中补充“只考虑不花钱的方案”；确认后续判断和最终结果同时满足两项要求，而非只回答最新一句。
5. 原生工具执行中补充，确认工具不被重复执行；模型声明仅回答补充时，不能冒充整任务成功。
