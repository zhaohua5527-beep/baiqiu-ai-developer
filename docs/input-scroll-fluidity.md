# 输入与历史滚动流畅度优化

## 调查边界

本轮实际进程 PID 23052、桌面“白球AI-测试-11”快捷方式及 9241 调试页面均指向 source-current。被动读取发现约 11,486 个 DOM 节点、62 条消息、371 个执行事件节点；采样时没有活动回复流或未发输入草稿。约七秒 CPU 采样以空闲为主，没有捕获持续卡死。因此不把此前每一次卡顿都归因于同一个缺陷。

本次只修改 renderer-v2/app.js 的输入测高与目录布局，不改事件、答案、Markdown、字体设计、模型请求或用户数据。没有刷新、重启当前应用，也没有发布。

## 已复现的低效操作

1. 每次普通输入都会把真实 textarea 高度设为 0，再读 scrollHeight、恢复高度并排队定位任务看板，即使最终高度未变也重复执行。
2. 滚动触发目录布局时，即使标题和宽度不变，仍重新显示所有按钮、逐个读取宽度并隐藏溢出项，同时重建“更多”菜单；逐个读写交错造成多次布局，并使打开的目录菜单自动关闭。

## 修改

- 用脱离文档流、不可聚焦的隐藏 textarea 测量内容，批量读取真实输入框排版属性后再写入测量节点。只有真实高度或溢出状态变化才修改可见输入框，只有高度改变才重新定位任务看板。
- 保留中文组合输入保护、草稿自动保存、手动拖高及字号缩放；测量节点不参与提交、读屏或聊天内容。
- 目录布局按可用宽度、字体、标题签名缓存；变化时批量读完按钮宽度再调整可见项。不再因普通滚动重建菜单，但宽度、字号和标题变化仍重新计算。
- 不减少历史消息、执行事件或阶段性回复，不以隐藏内容换取性能。

## 可复现验证

新测试 test/input-scroll-performance.test.js 在独立隐藏 Electron 窗口加载生产函数与样式，以 60 条合成历史构建约 1.1 万节点；使用临时用户目录，没有读写真实聊天或向模型发送请求。

同一轮预热后的前后比较：40 次单行输入，对真实输入框的样式写入从 80 次降至 0 次；40 次重复目录布局，目录 DOM 变更从 2040 次降至 0 次，Chromium 布局次数从 1024 次降至 1 次。“更多”菜单节点与展开状态得到保留。

首轮未预热时输入布局耗时曾为 110ms 对 8ms，但初始化差异会影响该值。预热后输入耗时接近，不能把首轮数据宣传为稳定倍数提升。可以确认的是无效可见高度重置与目录反复布局被消除；不保证所有机器、原生输入法或执行负载下完全无卡顿。

浏览器行为检查覆盖选择区与焦点、中文组合输入、草稿原文、同帧输入合并、多行增长与删除缩小、14/20/28px 字号、280/680px 输入宽度、手动高度、目录宽度变化和全部历史行保留。

证据及改动前备份：work/ui-smoothness-20260929/。layout-benchmark.txt 是隔离对比，regression-results.txt 是专项回归，baseline-anchor-results.txt 是旧源码的锚点测试结果。锚点测试中的三项失败在修改前同样出现：两项实现断言已过时，一项测试环境缺少 INSTRUCTION_ANCHOR_TOP_GAP；本轮未改这些无关断言或生产行为。

## 生效与回退

当前运行窗口没有被改动，避免打断任务或丢失内存中的补充队列。结合上一轮主进程和 preload 的模型设置修复，需要先处理当前任务及待发送内容，再完全退出并重新打开测试版；只关闭到托盘不够。回退仅撤销本轮测高和目录布局修改，不能整份覆盖 app.js，否则会丢失其他修复。
